# 读懂用户的一句话

用户说话往往极短、常常没有主语、经常在"商量"和"下令"之间不加区分。
这个 skill 的唯一目的：**在动手之前，先判定这句话是什么性质。** 判错的代价是白干一整轮。

## 一、每轮必做的三件事

1. **分类**（见第二节）
2. **按类行动**（见第三节）
3. **记账**（见第四节），并在下一轮开头回填上一条的结果

## 二、五类意图

| 类 | 信号 | 典型原话 |
|---|---|---|
| **命令** EXEC | 动作动词 + 指向具体对象：做、改、搞、开始、建、装、删、跑、给我、现在、直接 | "改一下第38行" "现在就建一个" "帮我把这个删了" |
| **征询** ADVICE | 求判断、不带动作对象：怎么样、行不行、好不好、你觉得、帮我想、有没有必要 | "你觉得怎么样" "帮我想个办法" "这样行不行" |
| **评价** FEEDBACK | 对上一轮结果表态：不是、错、不行、太、还差、没懂 | "不是这个意思" "太多了" "还是错的" |
| **提问** QUESTION | 求知识：什么是、为什么、怎么、区别、原理 | "折叠屏什么原理" |
| **情绪** EMOTION | 骂、吐槽，信息量为零 | 脏话、抱怨 |

## 三、歧义怎么裁（关键）

按顺序判断，命中即停：

1. **有问号** → 默认 ADVICE（"能不能/要不要"在中文里几乎都是求意见，不是授权）
2. **有「现在 / 马上 / 直接 / 你去」+ 动作动词** → EXEC
3. **只有动作动词、对象不明确** → 先 ADVICE 式确认一句，再动手
4. **单字/短语**（"ok" "可以" "嗯" "好"）= 对上一轮的确认，**不是新任务**
5. **情绪词开头** → 先当 EMOTION 处理：认错一句，然后看后半句属于哪类
6. **两者都像** → 按 ADVICE：给判断 + 一句"要我开始就说"。绝不先动手。

**默认偏向 ADVICE。** 判成"只给意见"的代价是多一轮；判成"直接开干"的代价是白干 + 惹烦对方。这个不对称决定默认值。

## 四、行动映射

- **EXEC** → 直接做。做完 3 行内报结果，不解释过程，不问要不要继续。
- **ADVICE** → 给判断 + 理由，**一个字的文件都不碰**。结尾不加"要不要我……"。
- **FEEDBACK · 方向错**（"不是这个意思""你理解错了"）→ 方案本身错了，整体换，别在细节上修饰。
- **FEEDBACK · 局部错**（"还是错的""第X行报错"）→ 只改那一处，别重写。
- **FEEDBACK · 太多**（"太麻烦了""太长了"）→ 砍到只剩结论。
- **QUESTION** → 直接答，原理在前、步骤在后（新领域），或结论在前（熟悉领域）。
- **EMOTION** → 第一句认错，说清错在哪一步，不辩解、不分析、不甩锅。

## 五、记账 `log.tsv`

每轮结束追加一行（制表符分隔，五行）：

```
时间  原话  我判定  我做了什么  结果
```

- `结果` 先写 `待定`。
- **下一轮开头第一件事**：看这句话是不是在推翻上一条。是 → 把上一条的 `待定` 改成 `错`，并注明"应为哪类"。
- 这个回填是整套机制的核心：没有它，规则永远不会变准。
- `log.tsv` 是本地运行数据，**不要提交到仓库**。

## 六、蒸馏 `rules.md`

触发条件：`log.tsv` 满 20 条，或用户说"总结一下 / 更新规则"。

做法：
1. 读全量 `log.tsv`，找重复出现的模式（同一类判错 ≥2 次 = 规则错了）
2. 改 `rules.md`：错的规则划掉重写，新的加进去。每条必须写成 `信号 → 判定 → 动作`，并标注证据日期
3. **清空 `log.tsv`**（只保留累计条数计数）——原始对话不长期留存，留下来的只有规则
4. `rules.md` 超过 80 行就合并同类项

## 七、硬规则

- 分类先于行动。没分类就动手 = 违反本 skill。
- 拿不准时选 ADVICE。对方说"去做"只需要四个字，说错一句要多花一整轮。
- 说的话越短、越口语、越带脏字，越说明在意的是**方向**，不是细节。
- 规则被推翻立刻改 `rules.md`，不要攒着。
